# 2026-11-16

- 관수 미션 실행 및 장비 통신 설계
  - 기존 미션 저장 흐름을 기준으로 준비·상태 조회·준비 취소 API의 요청과 응답 항목 정리
  - 시작·일시정지·종료 요청 이후 장비 응답에 따라 작업 상태가 바뀌는 흐름 정리
  - 실행 당시의 미션 버전과 내용을 보관하고, 실행 회차·장비 명령·상태 및 결과 보고를 각각 기록하는 DB 구조 초안 작성
  - 시작 버튼을 여러 번 눌렀을 때 중복 실행을 막고, 장비의 명령 수신 확인과 작업 완료 보고를 구분하는 기준 정리
  - 응답이 없으면 마지막으로 확인된 상태를 유지하고, 취소 뒤 도착한 응답이 상태를 되돌리지 않도록 처리 기준 정리
  - 실제 장비 연결 전 테스트 메시지로 확인할 수락·거부·무응답·중복 요청 사례 정리
  - 실내 시연 가능성을 고려해 좌표 형식은 장비팀과 협의할 항목으로 기록
  - [미션 실행 및 장비 통신 설계 초안](../docs/mission-execution-design.md)

- 운영 관리자 로그인 점검

  - 일반 브라우저에서 같은 이메일로 저장된 시연 계정이 먼저 처리돼 운영 API에 로그인 요청이 전달되지 않는 분기 확인
  - 시크릿 창에서 운영 계정 로그인 확인. 로그인 전 세션 조회의 401 응답과 로그인 요청 결과를 구분하는 방법 정리
