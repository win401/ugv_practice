# FE 개발 규칙

## 구조

- `views/`: 화면 단위 컴포넌트. 지도·패널 조합과 탭 공용 상태는 `WorkspaceView`에서 관리한다.
- `components/`: 헤더·정원 지도·장비 일러스트·종료 확인 창 등 화면을 구성하는 조각.
- `hooks/`: 타이머와 상태 전이 등 React 로직. 현재 장비 제어는 `useIrrigationSimulation`의 가상 동작이다.
- `api/`: 화면이 부르는 API 함수(`client.ts`)와 데이터 타입(`types.ts`). 지금 구현은 브라우저 안의 가상 서버(`mock.ts`)와 시연 데이터(`seed.ts`)다. 계약은 [API 계약](api.md).
- `admin/`: `/admin` 관리자 화면.
- `lib/`: React와 무관한 계산 함수.
- `types/`: 여러 파일이 공유하는 타입. 타입 가져오기는 `import type`을 사용한다.
- `styles/`: 공통 토큰·헤더·지도·패널·장비·이력·오버레이·반응형 규칙. `src/index.css`에서 순서대로 불러온다.

아이콘은 기존 `lucide-react`를 사용한다. 화면은 데이터를 직접 만들거나 저장하지 않고 `src/api/client.ts`의 `api`만 부른다. 백엔드와 연동할 때는 `ApiClient`의 구현만 바꾸고, 함수·경로가 바뀌면 [API 계약](api.md)과 환경변수(`FE/.env.example`)를 함께 고친다.

상태를 두는 곳은 종류에 따라 나눈다.

- 서버에서 받는 데이터(조회, 명령 결과, 실시간 수신 값)는 React Query로 관리한다. 기본 설정은 `src/api/queryClient.ts`에 있다. 등록·수정·명령은 실패해도 자동으로 다시 보내지 않는다.
- 화면 상태(탭, 입력값, 편집 초안, 선택한 정원·장비)는 React 상태로 둔다.
- 전역 상태 라이브러리는 쓰지 않는다. 떨어진 화면이 함께 봐야 하는 UI 상태가 생기면 그때 도입을 정한다.
- 가상 서버와 실서버는 같은 `ApiClient` 인터페이스를 구현한다.

실서버 요청은 `src/api/http.ts`의 `http()`만 거친다(안쪽은 axios). 화면이나 `httpApi.ts`에서 `fetch`나 `axios`를 직접 부르지 않는다. 그래야 오류 문구와 로그인 쿠키 처리가 한 곳에 모인다.

- 검색 조건은 주소에 이어 붙이지 않고 넷째 인자로 넘긴다. 예: `http("GET", "/api/admin/geocode", undefined, { query })`. 값이 없는 항목은 보내지 않는다.
- 요청이 0.3초 넘게 걸리면 전역 로딩 표시(`components/GlobalLoading`)가 화면 가운데에 뜨고 조작을 막는다. React Query를 거치는 요청에 자동으로 적용되므로 화면마다 로딩 표시를 따로 만들지 않는다.
- 서버가 거절하면 `ApiError`(상태 코드와 서버의 `detail`), 응답을 받지 못하면 "서버에 연결하지 못했습니다" 오류를 던진다.

## 이미지와 파일

- 화면 확인용 캡처·스크린샷은 저장소에 올리지 않는다. PR 본문이나 이슈에 첨부한다.
- `src/assets`의 이미지는 사용자가 매번 내려받는 파일이다. 화면에 보이는 크기의 2~3배 정도로 줄이고 WebP로 저장한다. 한 파일은 500KB 이하를 목표로 한다. 확대해서 보는 지도 배경처럼 원본 해상도가 필요한 경우만 예외로 하고 크기를 문서에 적는다.
- 로고·아이콘은 실제 벡터 SVG가 있을 때만 SVG로 둔다. PNG를 감싼 SVG(base64 이미지)는 무겁기만 하므로 WebP로 바꾼다.
- 쓰지 않는 이미지는 바로 지운다.

## UI와 상태

관수 작업의 running·paused·ready·done은 화면 시연용 상태다. 실제 장비 상태 전이로 해석하지 않는다. 자율주행·원격 제어·센서·통신 규격은 요구사항 확정 후 구현한다.

시연 데이터 기준일은 2026년 11월 4일이다. 데이터 날짜와 오늘 필터·화면 날짜를 변경할 때는 함께 확인한다. 가상 서버의 데이터는 `localStorage`(`saemgil-db-v2`)에 있어 새로고침해도 유지되고, 관리자 화면의 시뮬레이션 → 초기화로 되돌린다. 로그인은 탭마다 따로(`sessionStorage`) 유지한다.

모바일 구조 분기점은 768px이다. `.app`의 고정 화면 높이, `.workspace`·`.panel-body`의 `min-height: 0`, 패널 본문의 스크롤 구조를 유지한다. 반응형 규칙은 기본 규칙보다 뒤에 불러와야 한다. 새 버튼은 키보드 조작과 포커스 표시도 확인한다.

## 변경 확인

```bash
npm run format:check
npm run build
```

화면·상태 로직 변경 시 개발 서버에서 정원 전환, 일시정지·재개·종료·완료 이력, 장비·이력 탭, 모바일 본문 스크롤을 확인한다. 기능·실행 방법이 바뀌면 FE README와 관련 문서도 함께 갱신한다. 비밀정보는 코드·문서·스크린샷에 넣지 않는다.
