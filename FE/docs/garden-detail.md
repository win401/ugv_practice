# 전체 지도 / 정원 상세

## 화면별 역할

| 화면 | 역할 | 표시와 조작 |
| --- | --- | --- |
| 전체 지도 | 위치 확인과 편집 | V-world 위성지도에 경계, 예정 경로, 지나온 경로, UGV 표시. 구역 선택·추가·이름 및 경계 편집·미션 지점 편집 |
| 정원 상세 | 시각적 작업 현황 | 1536 × 1024 생성 이미지 위에 기본 구역 이름표, 예정 경로, 지나온 경로, UGV 표시. 확대·축소·이동 |

정원 상세는 폴리곤을 그리지 않으며 지도와 패널에서 구역 선택이나 미션 지점 편집을 제공하지 않는다. 화면에는 **실제 위치와 다를 수 있는 예시 화면**을 표시한다. 추가 구역의 선택은 상세의 선택 목록에서도 확인할 수 있다. 추가 구역의 지도 위치는 전체 지도에서 확인한다.

지도 전환은 선택한 구역, 미션 진행 현황, UGV 상태, 패널 탭을 유지한다. 구역 편집 중 상세로 전환하려면 저장하거나 취소한다. 미저장 구역 변경이 있으면 확인창을 표시한다. 미션 초안은 전체 지도로 돌아오면 계속 편집할 수 있다. 활성 회차의 비상정지 버튼은 두 지도에서 사용할 수 있다.

## 경계와 경로의 좌표

전체 지도에서 직접 편집한 경계의 꼭짓점과 곡선 조절점을 WGS84 `[경도, 위도]`로 저장한다. 화면에 그릴 때 Leaflet의 Web Mercator 투영을 사용한다. 브라우저에 저장한 경계는 상세 이미지의 개정 번호에 의존하지 않는다. 기본 A–X 경계와 이전 픽셀 편집본은 기존 배치를 예시 경계로 가져오므로 위성지도에서 확인하고 보정한다. [구역 저장 구조](garden-zone-api.md)

기존 가상 미션 지점과 UGV 경로는 시연 좌표를 사용한다. 전체 지도에서 미션 지점을 옮기면 Leaflet에서 찍은 위치를 기존 미션 좌표로 변환한다. 상세는 시연 좌표를 생성 이미지에 배치한다. 이미지 밖의 시연 위치는 이미지 가장자리로 제한한다. 새 구역은 관수 접근 지점을 연결한 뒤 경로를 미리 볼 수 있다.

## 장비 보고와 지도 이동

- 파란 점선은 예정 경로, 주황 실선은 지나온 경로다. 두 화면에서 같은 회차를 표시한다.
- 가상 장비 보고가 도착하면 마지막으로 그린 위치에서 방금 받은 위치까지 이어 그린다. 보고 사이에 다음 위치를 예측하지 않는다. 동작 줄이기 설정에서는 받은 위치를 바로 표시한다.
- 일시정지·작업 종료·안전정지·통신 끊김·미확인·장비 이상에서는 보간을 취소하고 마지막 화면 위치를 유지한다. 관수 효과는 신선한 보고에서 펌프 작동이 확인됐을 때 표시한다.
- 전체 완료율은 장비가 완료로 보고한 지점 수 기준이다. 경로 미리보기만으로 장비 위치나 완료율이 바뀌지 않는다.

`WorkspaceView`가 두 지도와 운영 패널을 연결한다. `useWorkspaceGardenScene`은 공통 선택·회차 상태를 각 지도 좌표로 그린다. `useIrrigationSimulation`이 보고 위치를 갱신하고, `useReportedMapProgress`가 보고된 위치까지의 화면 이동을 처리한다.

아래는 현재 역할 분리 이전의 이미지·배치·화면 검증 기록이다.

## 이미지와 좌표 수정 기록

아래 표는 공유 장면 분리 이전에 수정하고 검증한 문제의 기록이다.

사용자 확인에서 구역 선이 사진과 어긋나고, 확대하면 오른쪽 사진이 남으며, 미션 편집에서 예전 사진이 보이는 문제가 발견됐다.

| 문제                               | 원인                                                                                | 해결한 내용                                                                                                                | 확인 결과                                                                                       |
| ---------------------------------- | ----------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| 화단과 구역 선의 어긋남            | 새 이미지의 실제 배치와 일부 경계 좌표가 맞지 않았고 이미지·좌표 정보가 따로 관리됨 | 원본 1536 × 1024 기준으로 경계를 수정. 이미지 주소·크기·개정 번호를 한곳에서 관리하고 상세 API가 이미지와 좌표를 함께 반환 | 사진과 구역이 같은 변환을 사용하는지 확인. 24개 구역의 개별·조합 경로 검사 통과                 |
| 확대 후 오른쪽에 고정 사진 잔존    | 이동하는 사진 뒤에 고정 SVG 사진과 이전 CSS 배경이 겹쳐 있었음                      | 중복 배경을 제거하고 사진·구역·경로를 하나의 장면에서 확대·이동                                                            | 확대·이동 시 같은 사진 한 장만 표시되는지 확인                                                  |
| 동쪽 끝 구역 선택이 어려움         | 사진 끝과 패널이 가리는 영역을 함께 고려하지 못한 이동 범위                         | 가려지지 않는 지도 영역에서 가장자리 구역에 접근할 수 있도록 이동 범위 조정                                                | 동쪽 끝 W 구역까지 이동 후 지도에서 직접 선택 확인                                              |
| 미션 편집에서 이전 사진 표시       | 상세 지도와 미션 편집이 서로 다른 이미지·좌표를 사용                                | 미션도 공통 이미지 사용. 기본 운영 정원 3개의 경계·경로는 API 응답에서 현재 이미지에 맞춤                                  | 미션 탭·관수 작업 버튼의 현재 이미지 진입, 확대 후 지점 입력 확인                               |
| 확대·이동 후 지점 입력 오류 가능성 | 화면 좌표를 원본 이미지 좌표로 되돌리는 기준이 필요                                 | 실제 SVG 변환의 역행렬로 클릭 지점을 계산하고 클릭과 드래그를 구분                                                         | 확대·이동 후 지점이 클릭 위치에 표시되고, 드래그로 지점이 추가되지 않음                         |
| 경로가 화단을 가로지름             | 일부 길 선분을 화단 안쪽으로 연결                                                   | 접근 지점과 길 선분을 보이는 산책로로 수정                                                                                 | 길의 샘플 지점과 24개 선택 영역 검사에서 화단 내부 진입 0건. 실제 차량 폭·회전 반경 검증은 별도 |

개발 중 상세 API 구현이 바뀌면 자료를 다시 읽는다. 이미지 개정 번호가 바뀌면 선택·경로·이동 시연을 초기화한다. 지도 보기 방식이나 패널 탭을 바꾸는 동작은 이미지 개정 변경이 아니므로 공통 계획을 초기화하지 않는다.

기존 저장 자료는 일괄 덮어쓰지 않는다. `operatingGardenGeometry.ts`는 이전 기본 예시 경계 세 종류와 정확히 일치할 때만 **조회 응답**을 현재 좌표로 바꾼다. 정원 ID·고객·장비·이력은 유지한다. 사용자가 직접 그린 경계는 변환하지 않으며, 이전 사진 기준의 사용자 경계가 있다면 새 사진에서 별도 확인이 필요하다. 이 처리는 실제 지도 좌표로의 변환이 아니다.

## UGV 표현 방식

| 요소   | 현재 시안                                                    | 실제 장비 연동 시                                               |
| ------ | ------------------------------------------------------------ | --------------------------------------------------------------- |
| 위치   | 주황색 궤도형 아이콘을 이미지 픽셀 위치에 표시               | 장비가 보고한 위치를 지도 좌표로 변환해 표시                    |
| 방향   | 이동 구간 방향으로 차체·화살표 회전                          | 장비의 방위각 사용                                              |
| 이름표 | 이동 시연은 `UGV · 시연`, 운영 회차는 데모 장비 ID           | 실제 장비 ID·상태 표시                                          |
| 경로   | 파란 점선은 예정 경로, 주황색 실선은 시연 이동 이력          | 경로 계획과 실제 이동 이력을 각각 표시                          |
| 움직임 | ‘이동 시연’으로 길을 따라 이동하고 각 관수 지점에서 4초 정차 | 위치 보고 수신에 따라 갱신, 끊기면 마지막 위치와 수신 시각 표시 |
| 실행   | 실제 관수·장비 명령을 보내거나 운영 이력을 만들지 않음       | 작업 요청·수락·실행·중단 통신 규격 협의 후 연결                 |

구역 선택 후 이동 시연과 운영 미션 회차는 서로 다른 상태다. 다만 두 지도는 같은 상태를 보여주며, 진행 중인 운영 회차가 있으면 회차의 UGV를 우선한다. 구역 이동 시연은 예시 지점을 따라 움직이는 표현이며 실제 급수·정차·복귀 명령은 추가하지 않았다.

- 기존 기본 정원 조회 좌표 보정: `src/api/operatingGardenGeometry.ts`

## 예정된 작업

- 등록 정원의 실제 경계·위도·경도를 전체 지도에 연결
- 예시 구역 연결을 실제 정원 ID·구역별 상세 이미지·서버 접근 권한으로 확장
- 이미지 기준점과 실제 지도·장비 좌표의 변환 검증
- 장비 크기·회전 반경·장애물·정차 위치·급수 도달 범위 검증
- 실제 UGV 위치·방향·연결 상태 보고와 경로/작업 API 연결

## 확인 방법

1. 전체 지도에서 관수 구역을 선택하고 경계를 수정해 저장한다. 새로고침 후 경계가 같은 위치에 표시되는지 확인한다.
2. 정원 상세에서 선택 요약, 이름표, 예정 경로와 지나온 경로를 확인한다. 구역 경계선과 편집 도구는 전체 지도에서 확인한다.
3. 미션 탭에서 전체 지도 위의 지점을 옮긴다. 상세로 전환해 지도를 누른 뒤 전체 지도로 돌아와 미션 지점이 그대로인지 확인한다.
4. 관수 회차에서 두 지도를 전환하며 UGV와 완료율을 확인한다. 일시정지·비상정지와 통신 끊김을 시연해 표시가 멈추는지 확인한다.

## 검증 기록

- 데스크톱 1600px와 모바일 390px에서 실제 V-world 위성 타일 로딩, 구역 추가·곡선 변환·저장·취소, 새로고침 후 위도·경도 경계 복원, GeoJSON 다운로드를 확인했다.
