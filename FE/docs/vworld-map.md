# 순천만국가정원 전체 지도

## 확인한 사실

- 전체 지도는 Leaflet 1.9.4로 V-world 위성 타일을 표시한다. 정원·장비·관수 운영 자료는 가상 데이터다.
- 위성 타일은 HTTPS `Satellite/{z}/{y}/{x}.jpeg`로 요청한다. `y`는 TileRow, `x`는 TileCol이며 타일 요청은 기존 6~19단계를 유지한다. 화면은 최대 23단계까지 확대할 수 있고, 19단계보다 가까이 볼 때는 19단계 타일을 확대 표시한다.
- 공식 정원 안내 페이지의 지도 중심은 위도 `34.92923188877225`, 경도 `127.49889130642043`이다. 코드의 보기 범위와 관수 구역 배치는 화면 구성을 위한 예시이며 공식 경계가 아니다.
- 전체 지도에서 V-world 위성영상 위의 관수 구역을 선택·편집하고 미션 지점을 옮긴다. 저장 기준은 WGS84 위도·경도다.
- 정원 상세는 생성 이미지에 이름표, 예정 경로, 지나온 경로, UGV를 표시하는 예시 화면이다. 구역 경계선과 편집 도구는 전체 지도에 둔다.
- 초기 예시 경계와 이전 픽셀 저장본은 대략적인 위치를 가져온다. 위성영상에서 위치를 보정하면 그 위도·경도를 이후 경계로 사용한다. UGV의 가상 보고 위치는 예시 배치로 표시한다.
- 기존 예시 경계 3개는 공통 장면과 중복되지 않게 화면에서 숨긴다. 저장 자료와 사용자가 그린 추가 경계는 삭제하지 않는다.

## 키 입력과 실행

1. 회사 저장소의 `FE/.env.local`에 아래 항목을 설정한다. 기존 `API_PROXY_TARGET` 등 다른 값은 유지한다.

   ```dotenv
   VITE_VWORLD_API_KEY=발급받은_웹지도_키
   ```

2. V-world 인증키 관리에서 WMTS/TMS 활용 권한과 등록한 서비스 URL을 확인한다. 현재 개발 주소는 `http://127.0.0.1:5174/`다. `localhost`를 등록했다면 실제 접속 주소와 등록 정보를 맞춰 확인한다. 호스트·포트의 구체적인 허용 규칙은 V-world 키 관리 화면과 공식 안내를 따른다.
3. 실행 중인 개발 서버를 `Ctrl+C`로 종료하고 `FE`에서 `npm run dev`로 다시 실행한다. Vite는 시작 시 환경 파일을 읽는다.
4. 로그인 후 **전체 지도**에서 순천만국가정원의 위성영상이 나오는지 확인한다.

`.env.local`은 Git에서 제외하고 Docker 빌드에도 포함하지 않는다. `VITE_` 값은 브라우저 코드에 들어가므로 비밀 저장소가 아니다. 이 설정은 브라우저용 지도 키에만 사용하며, DB 비밀번호·서버 토큰을 넣지 않는다. 실제 키를 채팅·스크린샷·커밋에 남기지 않는다.

배포 파일은 Secret Manager의 키를 빌드 시 전달하도록 수정했다. 2026-11-12 회사 프로젝트에서 시크릿 생성과 배포 계정의 읽기 권한 설정을 조회로 확인했다. Cloud Run 배포는 아직 실행하지 않았다. `VITE_` 값은 빌드 시 들어가므로 정적 FE 컨테이너에 실행 환경변수만 추가해도 기존 빌드 파일의 지도 키가 바뀌지는 않는다.

## 확인 순서

- 지도가 비어 있으면 `.env.local` 입력 → 개발 서버 재시작 → WMTS/TMS 사용 설정 → 서비스 URL·키 유효기간 → 외부 네트워크 순서로 확인한다.

- 위성 영상은 제공 시점의 촬영 자료이며 실시간 정원 영상이 아니다.

## 상세 지도와 기본 배율 맞추기 — 2026-11-12

`lib/gardenCamera.ts`에서 상세 이미지의 화면 채움 배율, 패널을 피하는 중심점, 사진 가장자리의 이동 범위를 함께 계산한다. 전체 지도는 그 배율을 소수점 Leaflet 줌으로 바꾸므로 정수 줌 단위 때문에 정원이 작아지지 않는다. 기본 보기에서 화면 크기를 바꾸면 다시 맞추고, 사용자가 직접 이동·확대한 화면은 그대로 조작할 수 있다. ‘정원 전체 보기’를 누르면 공통 기본 보기로 돌아간다.

- `maxZoom: 23`: 화면에서 허용하는 최대 확대 단계.
- `maxNativeZoom: 19`: 서버에 요청할 원본 타일의 최대 단계. 20~23단계 타일을 새로 요청하지 않는다.
- `zoomSnap: 0`: 기본 이미지 배율에 맞는 소수점 줌 허용.
- 버튼 한 번의 변화: `log2(1.25)`단계, 화면 크기 약 25% 증가.

타일 확대 방식은 [Leaflet 1.9.4의 maxNativeZoom](https://leafletjs.com/reference-1.9.4.html#gridlayer-maxnativezoom)을 따른다. 19단계 이후에는 위성사진이 흐릿해질 수 있다. 생성 이미지와 위성사진의 식재·길 모양은 다르며, 두 화면의 첫 보기 배율과 중심점을 맞춘 것이다.

### 콘솔 설정 방법

Secret Manager는 보관 중인 버전 수와 조회 횟수에 따라 과금된다. 월 무료 한도인 버전 6개·조회 10,000회는 결제 계정 전체에 합산되므로 이번 시크릿이 반드시 무료라고 가정하지 않는다. 사용을 마치면 불필요한 버전을 파기하거나 시크릿을 삭제한다. 사용 중지된 버전도 보관 요금 대상이다. [공식 요금](https://cloud.google.com/secret-manager/pricing)

1. GCP 콘솔 상단에서 회사 프로젝트 `saemgil-513906`을 선택한다.
2. 검색창에서 **Secret Manager**를 열고 API 사용 설정 안내가 나오면 활성화한다.
3. 전역 시크릿 **만들기**에서 이름을 `vworld-api-key`로 입력한다.
4. 값에는 발급받은 지도 키 문자열만 붙여 넣는다. `VITE_VWORLD_API_KEY=`나 따옴표를 함께 넣지 않는다. 자동 복제와 기본 암호화를 사용한다.
5. 생성 후 버전 `1`이 사용 설정 상태인지 확인한다. [시크릿 생성 공식 안내](https://docs.cloud.google.com/secret-manager/docs/creating-and-accessing-secrets)
6. 이 시크릿의 권한에서 **주 구성원 추가**를 선택하고 `sa-github-deployer@saemgil-513906.iam.gserviceaccount.com`에 **Secret Manager Secret Accessor** (`roles/secretmanager.secretAccessor`)를 부여한다. 시크릿 하나의 권한 범위에서 설정한다. [시크릿 접근 권한 안내](https://docs.cloud.google.com/secret-manager/docs/manage-access-to-secrets)
7. V-world 키 관리에서 실제 배포 주소의 서비스 URL 등록을 확인한다. 키 값은 채팅·커밋·스크린샷으로 공유하지 않는다.

배포 계정이 빌드할 때만 읽으므로 실행 계정 `sa-frontend`에 이 시크릿의 접근 권한을 추가할 필요는 없다. 로컬 개발은 기존 `.env.local`을 유지할 수 있다.

### 완료한 코드 변경

```text
Secret Manager: vworld-api-key/latest
  → GitHub Actions: 기존 WIF 배포 계정으로 읽기
  → Docker BuildKit: 빌드 명령에만 VITE_VWORLD_API_KEY 제공
  → Vite: 지도 키가 포함된 dist 생성
  → nginx / Cloud Run: 완성된 정적 파일 제공
```

- `.github/workflows/deploy-fe.yml`: 대상 프로젝트를 명시하고 키를 권한 제한 임시 파일로 읽는다. 키가 비어 있거나 조회에 실패하면 이미지 push/배포 전에 중단한다. 단계 종료 시 임시 파일을 삭제한다.
- `FE/Dockerfile`: `RUN --mount=type=secret`으로 `npm run build`에만 키를 제공한다. 키를 `ARG`나 영구 `ENV`에 기록하지 않는다.
- PR CI에서는 시크릿 없이 빌드하고, 운영 배포 단계에서는 키를 필수로 확인한다. CI에 GCP 접근 권한을 추가하지 않았다.
- 키 변경이 빌드 캐시에 반영되도록 배포 빌드에 `--no-cache-filter build`를 적용한다. [Docker 빌드 시크릿](https://docs.docker.com/build/building/secrets/) · [캐시 규칙](https://docs.docker.com/build/cache/invalidation/)
- Vite가 만든 JavaScript와 브라우저 지도 요청에는 키가 포함된다. Secret Manager 사용은 저장·전달을 관리하는 것이며 브라우저에서 키를 숨기는 기능이 아니다. [Vite 환경변수](https://vite.dev/guide/env-and-mode#env-variables)

새 키로 바꾸려면 시크릿의 새 버전을 추가하고 **Deploy FE**를 다시 실행한다. 시크릿 값만 바꿔서는 기존 배포의 JavaScript가 갱신되지 않는다. `latest`가 사용 중지되었거나 파기된 버전이면 읽기에 실패할 수 있으므로 사용할 최신 버전을 확인한다.
