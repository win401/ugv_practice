# 전체 지도에서 추가 정원 경계 관리

## 확인한 사실

- 전체 지도에서 기본 A–X 관수 구역과 직접 추가한 관수 구역을 선택·편집한다. `api.gardenZones`가 위도·경도 경계를 고객·지도별로 저장한다. [관수 구역 편집](garden-zone-editing.md)
- **전체 지도 → 정보 → 추가 정원 경계 관리**는 별도의 관리 목록이다. 여기서 작성한 경계는 `api.gardenAreas`에 위도·경도로 저장하며 관수 구역 목록에 합쳐지지 않는다.
- 이전 예시 경계 3개는 관리 목록과 지도에서 숨긴다. 추가 경계를 선택하면 전체 지도에서 위치를 확인할 수 있다.
- 정원 상세는 생성 이미지, 이름표, 예정·지나온 경로와 보고 기반 UGV 상태를 보여 준다. 경계와 미션 지점 편집은 전체 지도에서 수행한다. 장비 정지 또는 상태 미확인 시 표시 위치를 유지한다.
- 추가 정원 경계는 위치 확인용이다. 운영 정원 등록, 장비 배정, 미션과 관수 실행은 각각의 기능에서 처리한다.

## 사용 방법

1. 전체 지도의 정보 탭에서 **추가 정원 경계 관리**를 누른다.
2. **구역 추가**를 누르고 이름을 입력한다.
3. 지도에서 경계 모서리를 순서대로 누른다. 최소 3개, 최대 30개이며 드래그·확대·축소로 위치를 찾을 수 있다.
4. **구역 저장**을 누른다. 마지막 점 취소·점 모두 지우기·작성 취소도 제공한다.
5. 목록 또는 지도 경계를 눌러 전체 지도에서 그 위치를 확인한다. 삭제에는 확인 창이 표시된다.
6. **관수 구역으로 돌아가기**를 누르면 관수 구역 선택 화면으로 돌아온다.

작성 중 이동할 때는 미저장 경계가 있으면 확인한다. 이 경계 관리와 미션 초안 편집은 별도 상태이며, 미션 초안은 전체 지도/정원 상세 전환만으로 버리지 않는다.

## 저장과 API

`api.gardenAreas`는 브라우저 내부의 비동기 목업 API다. HTTP 요청이나 Cloud SQL 쓰기는 없다.

| 함수                                  | 역할                                                                                        |
| ------------------------------------- | ------------------------------------------------------------------------------------------- |
| `list(scopeId)`                       | 고객/사용자의 경계 조회. 저장이 없으면 기존 예시 3개도 반환하지만 현재 관리 화면에서는 숨김 |
| `create(scopeId, { name, boundary })` | 이름과 위도·경도 경계 검증 후 저장                                                          |
| `remove(scopeId, id)`                 | 지정 경계 삭제                                                                              |

- `boundary`는 `[위도, 경도]` 쌍의 배열이다. 마지막에 첫 점을 반복하지 않는다.
- 저장 키는 `saemgil-garden-areas-v1:<고객 또는 사용자 ID>`이며 운영 가상 DB·미션 저장과 분리한다.
- 화면에서 숨긴 예시 자료를 저장소에서 삭제하지 않는다. 사용자가 명시적으로 삭제한 경계는 새로고침해도 복원하지 않는다.
- 자료가 손상되거나 저장 공간이 부족하면 오류를 표시하고 기존 자료를 덮어쓰지 않는다.
- 다른 컴퓨터와 공유되지 않는다. 다른 탭에서 변경한 경계는 새로고침으로 확인한다. 기존 관리자 전체 데이터 초기화는 이 별도 목록을 초기화하지 않는다.
- scope 구분은 목업 저장 분리이며 서버 권한 검사를 대신하지 않는다.
