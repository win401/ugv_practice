# API 계약

프론트엔드가 부르는 API 함수(`src/api/client.ts`의 `ApiClient`)와 백엔드의 HTTP 경로를 정리한다. 함수·경로가 바뀌면 이 문서와 `ApiClient`를 함께 고친다.

## 두 가지 구현

`ApiClient`의 구현은 둘이고, 화면은 어느 쪽인지 모른다. `src/api/client.ts`의 `api`가 로그인한 계정에 따라 고른다.

| 구현      | 파일                                    | 쓰는 계정                                                                           | 데이터가 있는 곳        |
| --------- | --------------------------------------- | ----------------------------------------------------------------------------------- | ----------------------- |
| 가상 서버 | `src/api/mock.ts`, `src/api/seed.ts`    | 가상 데이터에 있는 계정. 시연 계정 2개와, 시연 관리자가 그 브라우저에서 추가한 고객 | 브라우저 `localStorage` |
| 실제 서버 | `src/api/httpApi.ts`, `src/api/http.ts` | 그 외 계정                                                                          | 백엔드(MySQL)           |

- 로그인할 때 이메일(앞뒤 공백 제거, 소문자 비교)이 가상 데이터에 있으면 가상 서버로, 없으면 실제 서버로 보낸다. 가상 데이터 계정은 실제 서버를 부르지 않는다.
- 로그인한 뒤에는 그 탭이 가상 서버에 로그인돼 있으면 가상 서버를, 아니면 실제 서버를 쓴다. 로그인·로그아웃은 페이지를 새로 불러오므로 한 화면에서 두 쪽이 섞이지 않는다.
- 가상 데이터에서 추가한 계정·정원은 그 브라우저에만 있고, 실제 서버에서 추가한 것은 서버에만 있다.
- 지금 계정이 가상 데이터 계정인지는 `isDemoSession()`으로 안다. 가상 데이터 안내 문구처럼 계정 종류에 따라 달라지는 표시에 쓴다.
- 서버에서 받은 데이터는 React Query가 보관한다(`src/api/queryClient.ts`, `src/api/useApiData.ts`). 등록·수정이 성공하면 받아 둔 데이터를 다시 불러온다. 주소 검색 결과는 검색어별로 5분 동안 받아 둔다.
- 로그인 확인(`auth.session`)이 서버에 닿지 못해 실패하면 화면은 로그인하지 않은 것으로 본다. 백엔드 없이도 로그인 화면이 나오고 가상 데이터 계정으로 들어갈 수 있다.
- 받아 둔 데이터가 있으면 뒤에서 하는 재확인이 실패해도 화면을 유지한다. 오류 화면은 처음부터 받지 못했을 때만 보여 준다.

실제 서버의 응답은 `httpApi.ts`가 화면이 쓰는 모양으로 바꾼다: id는 글자로, 날짜는 `2026.11.13` 형식으로, 지역은 주소 앞 두 마디로 만든다.

실제 서버가 "없음"인 항목은 아직 작업을 시작하지 않았다. 맡아서 구현하거나 아래 제안 경로를 바꿔도 된다. 바꾸면 이 문서와 `ApiClient`를 함께 고친다.

실제 계정에서도 운영 화면의 관수 구역 A~X와 미션은 순천만국가정원 기준의 시연 자료다. 서버에 등록한 정원의 위치와 맞지 않으므로, 등록 위치가 있는 정원(`Garden.geo`가 있는 정원)을 고르면 전체 지도에서 시연 구역·예시 경계·장비 표시를 숨기고 그 정원의 경계만 그린다. 정원 상세도 예시 그림 대신 위성지도에서 그 정원만 보여 준다.

## 공통

- 모든 경로는 `/api`로 시작한다. 개발 서버는 `/api` 요청을 로컬 백엔드(`http://localhost:8080`)로 넘긴다. 주소를 바꾸려면 `FE/.env.local`에 `API_PROXY_TARGET`을 둔다(`FE/.env.example` 참고).
- 요청·응답 본문은 JSON이고, 형태는 `src/api/types.ts`의 타입과 같다.
- 실제 서버의 로그인 상태는 `HttpOnly` 쿠키(JWT)로 유지한다. 화면 코드는 쿠키를 읽을 수 없어 `GET /api/auth/me`로 로그인한 사람을 확인한다. 가상 서버는 탭마다 `sessionStorage`에 둔다.
- 응답 규칙은 [BE README의 API 응답 규칙](../../BE/README.md#api-응답-규칙)을 따른다. 성공하면 데이터를 감싸지 않고 그대로 보낸다.
- 실패 응답은 ProblemDetail(`application/problem+json`)이다. 화면은 `detail`을 그대로 보여 준다. 가상 서버는 같은 문장을 `ApiError.message`로 던지고, 실제 서버 구현(`http.ts`, 안쪽은 axios)은 `detail`을 `ApiError.message`로 옮긴다.
- 실제 서버는 날짜·시간을 ISO 형식 한국 시간(예: `2026-11-04T09:20:00`)으로 준다. `types.ts`는 화면 표시 형식(`2026.11.04`, `2026.11.04 09:20`)을 쓰므로 `httpApi.ts`가 바꾼다.
- 등록·수정·삭제는 실패해도 자동으로 다시 보내지 않는다. 조회는 네트워크 문제일 때만 한 번 다시 시도한다.

| 코드 | 뜻                                                           |
| ---- | ------------------------------------------------------------ |
| 400  | 입력값 오류                                                  |
| 401  | 로그인 필요, 또는 이메일·비밀번호 불일치                     |
| 403  | 권한 없음, 또는 정지된 계정                                  |
| 404  | 대상 없음. 운영자가 남의 정원에 접근할 때도 404로 숨긴다     |
| 409  | 현재 상태와 충돌 (이름 중복, 승인 전 관수, 장비 오프라인 등) |

## 권한 규칙 (서버에서 반드시 검사)

- `/api/admin/**`은 `role = admin`만 호출할 수 있다.
- 운영자 API(`/api/me/**`)는 로그인한 운영자의 정원·장비·기록만 다룬다. 정원 소유자(`customerId`)를 서버에서 확인한다.
- 관리자도 운영 화면(`/`)으로 로그인 후 들어온다. 운영자 API를 호출할 수 있고, 자기 정원과 정원이 있는 운영자의 화면을 골라서 본다.
- 정원 주인은 운영자와 관리자 모두 될 수 있다.
- 정원 등록은 관리자만 한다(`POST /api/admin/gardens`). 운영자에게는 정원 등록 API가 없다.
- `status = suspended` 계정은 로그인과 모든 API가 거절된다.
- 화면에서 메뉴를 숨기거나 경로를 막는 것은 안내용이다. 보안은 위 서버 검사로만 보장된다.

`deleteCustomer`, `deleteGarden`, `searchAddress`는 `ApiClient`에서 선택 항목이다. 가상 서버에는 없어서 화면은 실제 계정에서만 해당 버튼과 입력란을 보여 준다.

`updateGarden`의 서버 규칙:

- 장비 한 대는 한 고객의 정원만 맡는다. 다른 고객의 정원을 맡은 장비를 배정하면 409.
- 소유자를 바꾸면 장비 배정을 함께 푼다.
- 작업 중이던 정원에서 장비가 빠지면 그 장비는 대기로 바뀐다.
- 실제 서버는 지역(`region`)을 저장하지 않는다. 화면에서 지역만 고치면 반영되지 않는다.
- 실제 서버는 면적을 소수 둘째 자리로 맞춰 저장한다. 맞춘 값이 0이면(예: `0.001`) 400으로 거절한다.
- 실제 서버는 같은 정원의 동시 수정, 같은 계정의 동시 정원 등록·이름 변경, 같은 장비의 동시 배정을 한 번에 하나씩 처리한다. 뒤에 온 요청은 앞 요청이 저장한 값을 보고 처리되거나 409로 거절된다.
- 실제 서버는 위치와 경계를 `geo` 하나로 받아 중심 좌표·경계 원본·GeoJSON 넷을 함께 바꾼다. 화면은 경계를 고쳤을 때만 `geo`를 보낸다. 주소만 고치면 글자만 바뀌고 지도의 위치는 그대로다.

### 실제 정원의 위치와 경계 (`Garden.geo`)

실제 서버의 정원은 위경도(WGS84)로 위치를 갖는다. 좌표 순서는 `[경도, 위도]`다. 가상 데이터의 정원에는 `geo`가 없고, 실제 정원에는 사진 기준 자료(`shape`, `label`, `route`)가 비어 있다.

| 필드       | 의미                                                                                            |
| ---------- | ----------------------------------------------------------------------------------------------- |
| `center`   | 경계의 중심 `[경도, 위도]`                                                                      |
| `boundary` | 화면에서 그린 경계 원본. `{ kind, points }` 목록이며 `M` 시작, `L` 직선, `Q`·`C` 곡선, `Z` 닫기 |
| `geojson`  | 곡선을 짧은 직선으로 나눈 GeoJSON `Polygon`. 처음 점과 마지막 점이 같다                         |

등록 화면(`src/admin/AddGeoGardenForm.tsx`, `GardenBoundaryMap.tsx`)이 위성지도에 그린 경계에서 세 값과 면적을 계산한다(`src/lib/gardenBoundary.ts`). 경계 계산은 관수 구역 편집과 같은 `src/lib/zoneGeometry.ts`를 쓴다. 서버는 형식·닫힘·점 개수·좌표 범위만 검사하고 교차 여부는 화면이 검사한다.

## 변경 알림

`api.onChange(listener)`는 가상 서버의 데이터가 바뀌었을 때(다른 탭 포함) 알린다. `src/main.tsx`가 이 알림을 받아 React Query가 받아 둔 데이터를 다시 불러온다.

실제 서버는 변경을 알려 주지 않는다. 등록·수정·삭제가 성공하면 화면이 받아 둔 데이터를 다시 불러온다. 다른 사람이 바꾼 내용은 화면을 다시 열거나 다음 조회 때 보인다. 주기적 재조회와 실시간 전달(SSE)은 아직 없다.

## 공통 정원 시안 자료

아래 함수는 `src/api/gardenDetail.ts`에서 구현한 브라우저 내부 목업이다. 전체 지도와 정원 상세가 같은 응답 자료를 사용한다. HTTP 경로는 아직 정하지 않았으며 네트워크 요청·운영 미션 생성·장비 명령을 실행하지 않는다.

| 함수                            | 결과            | 용도                                                                        |
| ------------------------------- | --------------- | --------------------------------------------------------------------------- |
| `gardenDetail.read()`           | `DetailMapData` | 이미지 주소·개정 번호·크기, 24개 구역 경계, 예시 길, UGV 시작점을 함께 반환 |
| `gardenDetail.preview(zoneIds)` | `DetailPlan`    | 선택한 화단의 접근 지점을 연결한 픽셀 좌표 경로와 방문 순서                 |

`DetailMapData`의 이미지와 좌표는 한 묶음으로 취급한다. 이미지만 새것으로 바꾸고 이전 좌표를 남기지 않도록 같은 응답에서 받는다.

| 필드              | 의미                                                  |
| ----------------- | ----------------------------------------------------- |
| `imageUrl`        | 이번 좌표 자료에 맞는 상세 이미지 주소                |
| `imageRevision`   | 이미지·좌표 자료의 개정 번호. 현재 `suncheon-wide-v2` |
| `width`, `height` | 원본 이미지의 픽셀 크기. 현재 1536 × 1024             |
| `zones`           | A–X 24개 선택 구역의 ID·이름·경계·표식 위치·접근 지점 |
| `paths`           | 같은 이미지 픽셀 기준의 예시 길 선분                  |
| `dock`            | 시연 출발점의 이미지 픽셀 위치                        |

주소·크기·개정 번호는 `src/lib/gardenImage.ts`의 `GARDEN_IMAGE`에서 함께 관리한다. 이 자료는 상세 이미지와 예시 경로에 사용한다. 전체 지도에서 저장한 관수 구역은 위도·경도 기준의 별도 자료다.

구역 ID가 비어 있거나 정의되지 않은 ID가 포함되면 미리보기를 거부한다. 거리 필드는 픽셀 길이로 실제 미터가 아니다. UI는 선택 구역이나 이미지 개정 번호가 바뀌면 기존 계획과 시연을 초기화한다. 전체 지도 API 및 실제 장비 위치 연결은 별도 협의 대상이며 [정원 상세 안내](garden-detail.md)를 참고한다.

기본 운영 정원 조회에는 `src/api/operatingGardenGeometry.ts`의 응답 변환을 적용한다. 이전 기본 경계 3종과 정확히 일치할 때만 현재 이미지에 맞는 경계·표식·경로를 반환한다. 저장된 운영 가상 DB, 정원 ID·고객·장비·이력, 직접 그린 사용자 경계는 다시 쓰지 않는다. 이는 실제 위도·경도 변환이 아니며 이전 사용자 경계의 위치를 자동 보정하지 않는다.

## 지도 화면과 장비 보고

`useWorkspaceGardenScene`은 선택 상태, 경로 미리보기와 장비 보고를 두 지도에 전달한다. 전체 지도는 위성 타일 위에 지리 경계와 시연 경로를 그리고, 정원 상세는 생성 이미지에 이름표·예정 경로·지나온 경로·장비를 표시한다. 미션 초안과 구역 경계 편집은 전체 지도에서만 처리한다.

`Run.reportedProgress`는 마지막 가상 장비 보고에서 확정된 경로 진행률이다. 화면 보간은 마지막 표시 위치와 보고된 위치 사이에서만 진행한다. 일시정지·종료·안전정지·통신 끊김·미확인 시 표시를 멈춘다. [장비 보고와 지도 이동](garden-detail.md)

전체 지도 배경은 Leaflet에서 V-world WMTS 위성 타일을 요청한다. 키 설정과 실패 상태는 [V-world 안내](vworld-map.md)를 참고한다. 위도·경도 경계는 `gardenZoneProjection.ts`로 투영하고, `gardenGeoFrame.ts`는 예시 배치와 이전 픽셀 자료 변환에 사용한다.

## 지도 정원 구역 목업

`api.gardenAreas`는 `src/api/gardenAreas.ts`에서 구현한다. 운영 정원 등록 API와 별개이며 HTTP 경로는 아직 정하지 않았다.

| 함수                                              | 결과           | 역할                                 |
| ------------------------------------------------- | -------------- | ------------------------------------ |
| `gardenAreas.list(scopeId)`                       | `GardenArea[]` | 고객/사용자별 로컬 구역 조회         |
| `gardenAreas.create(scopeId, { name, boundary })` | `GardenArea`   | 위도·경도 경계 검증 및 브라우저 저장 |
| `gardenAreas.remove(scopeId, id)`                 | `void`         | 구역 삭제                            |

`GardenArea`는 `id`, `name`, `boundary: [위도, 경도][]`, `detailKind`, `isExample`, `createdAt`을 갖는다. `createdAt`은 UTC ISO 문자열이다. 기존 `detailKind`는 저장 자료 호환을 위해 유지하며 새 경계에는 `satellite`를 기록한다. 현재 화면은 `isExample`인 초기 3개를 표시에서 제외하지만 저장소에서 삭제하지 않는다. 직접 만든 경계는 전체 지도의 별도 관리 목록에서 위치를 확인하며 공통 24개 관수 구역이나 운영 미션에 자동 합치지 않는다. scope는 목업 저장 분리용이며 실제 인증·권한 검사를 대체하지 않는다. [저장 범위와 검증](garden-areas.md)을 참고한다.

## 현재 구조 확인 상태

위 내용은 통합한 구현과 타입 정의 기준이다. 2026-11-12 지도 전환 시 상태 공유, 미션 초안 유지·저장, 예시 경계 숨김·저장 보존과 빌드·브라우저 검증을 통과했다. 확인 범위는 [정원 상세 검증 목록](garden-detail.md#검증)에 기록했다.

### UGV 이동·분사 표시 모델

공통 지도 UGV 모델에 `status`(대기·이동·관수·일시정지·정지·완료·상태 확인)와 `wateringSide`(`left` / `right` / `null`)를 추가했다. 현재 값은 브라우저 시연용이다. 좌우 노즐 상태는 향후 장비 보고 필드와 연결하며 이번 작업에서 서버 API나 장비 명령 계약을 확정하지 않았다.

운영 시연의 `Run.movement`는 출발·도착 이미지 좌표, 누적 이동 시간, 구간 소요 시간, 재개 시각을 보관한다. 실제 장비 좌표가 아니라 가상 회차 위치를 연속 표시하기 위한 선택 필드다. 관수 상태·완료·ACK는 기존 보고 흐름으로 관리한다.

## 관수 구역 편집의 브라우저 저장 API

`api.gardenZones`는 비동기 `read`, `create`, `update`를 제공한다. 현재 어댑터는 브라우저 저장을 사용한다. 화면의 편집 초안을 WGS84 `[경도, 위도]` 경계로 변환해 `schemaVersion: 3` DTO에 저장한다. 키는 `saemgil-garden-zone-edits-v3:<scopeId>:<mapId>`이며 이미지 개정과 별도로 유지한다. v1·v2는 읽을 때 예시 경계로 변환하고 다음 저장부터 v3을 쓴다. [구역 저장 모델과 BE 연동 계약](garden-zone-api.md)
